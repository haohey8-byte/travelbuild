# PRD · 经典路线（案例）三角色共创

> 状态：✅ 已落地（决策点：① 角色自发布 ② 改名「从行程定制导入」；代码已实现，待部署后三角色验证）
> 作者：产品通（Product Management Expert）
> 关联：`doc/ONBOARDING.md`、案例模块 `backend/src/modules/case/*`、`frontend/src/views/Cases.vue`

## 1. 背景与问题

【经典路线】是 PandaKing9 平台对外的精品行程展示（案例）。产品定位是**三角色共创内容**：PandaKing（平台）、境外旅行社（agency）、省地接社（provincial）都应能贡献经典路线。

现状（已核对代码）存在断点：

- 三个创建入口（新建空白案例 / 导入 HTML 微站 / 从路线派生）虽对所有登录用户可见，但**省地接社是死路**：
  - 省地接社无 `agencyId`，自建/派生的草稿 `agencyId=null` → 列表过滤只返回"已发布" → **自己建的草稿看不到**；
  - 发布/下线/删除/翻译全部 `assertPandaking`（仅 PandaKing）→ 建了也发不出去。
- 境外旅行社能看到本机构草稿，但发布仍需 PandaKing，只能"校对"。
- "从路线派生"语义正确（把【行程定制】里的路线转成【经典路线】脱敏草稿），但"派生"是开发黑话，三角色都难秒懂。

## 2. 目标

- 三角色均可使用全部三种创建方式（空白 / 导入 HTML / 从行程定制导入）。
- 每个角色都能看到并管理**自己**创建的案例草稿（修掉省地接社死路）。
- 采用**角色自发布**模型：三角色均可发布自己创建/归属的案例，对外即时显示；PandaKing 保留对任意案例的接管与管控权。
- "从路线派生"改名为**「从行程定制导入」**，让三角色（尤其非技术的省地接社）一眼看懂来源与结果。

### Non-goals（本次不做）

- 不改三角色数据隔离（agency 仍看不到他机构草稿；provincial 仅看已发布 + 自己创建）。
- 不改分享页 SSR 渲染、联合品牌（via=agencyId）逻辑本身。
- 不改 AI 翻译（TMT）流程，仅发布时沿用既有自动补翻 En/Th。
- 不改"agency 对他人案例仅可校对"的协作关系。

## 3. 角色 × 操作权限矩阵（共创模型）

| 操作 | PandaKing | 境外旅行社 (agency) | 省地接社 (provincial) |
|---|---|---|---|
| 新建空白案例 | ✅ | ✅ | ✅ |
| 导入 HTML 微站 | ✅ | ✅ | ✅ |
| 从行程定制导入 | ✅ | ✅ | ✅ |
| 看自己草稿 | ✅ | ✅（本机构 agencyId） | ✅（本人 createdById） |
| 看全网已发布 | ✅ | ✅ | ✅ |
| 编辑自己案例 | ✅ 全字段 | ✅ 全字段（本机构） | ✅ 全字段（本人创建） |
| 发布 / 下线 / 删除 | ✅ 任意 | ✅ 本机构归属案例 | ✅ 本人创建案例 |
| 接管/管控他人案例 | ✅ | ❌ | ❌ |

### 发布模型说明（已确认：角色自发布）
- agency 发布本机构案例 → 对外走**「联合定制旅行」**品牌（via=该机构自动带联合品牌，沿用既有机制）。
- provincial 发布本人案例 → 对外走 **PandaKing9 单品牌**（省地接社无独立品牌档案，作为目的地内容贡献）。
- PandaKing 保留对任意案例的发布/下线/删除权，作为品牌兜底与质量管控。

## 4. 归属与可见性规则

- `createdById` = 创建人；`agencyId` = 创建人机构（provincial / 无机构 = null）。
- **派生案例归属"创建人"**（而非源路线机构），保留 `sourceRouteId` 溯源字段。
  - 修正现状隐患：`case.service.publishFromRoute` 当前把 `agencyId` 设为源路线机构（line 203）；应改为创建人机构。
- 列表可见性（`listAll`，已半修）：
  - pandaking：全量；
  - agency：本机构全部状态 + 全网已发布；
  - provincial：本人创建全部状态 + 全网已发布（**修掉"看不到自己草稿"死路**）。

## 5. 用户故事

- 作为 **省地接社**，我希望在【经典路线】点"从行程定制导入"选一条我参与的路线，生成脱敏草稿并能在列表看到它、补全后自行发布，以便我把目的地经验变成平台经典路线。
- 作为 **境外旅行社**，我希望新建/导入/从行程定制导入案例，并直接发布本机构经典路线（带联合品牌），以便展示我社产品。
- 作为 **PandaKing**，我希望三角形色自由共创，同时保留对任意案例的下线/删除/接管权，以便把控平台品牌与质量。
- 作为 **任意角色**，我希望按钮叫"从行程定制导入"而非"从路线派生"，以便秒懂这是把【行程定制】的路线变成【经典路线】。

## 7. 技术改动清单（交技术专家）

### 后端 `case.service.ts` / `case.controller.ts`
1. **`listAll` 可见性补强**：provincial（及任何角色）加上"本人创建"可见条件——`OR:[{status:'published'},{createdById:user.id}]`（pandaking 全量、agency 本机构+已发布 维持）。
2. **`publishFromRoute` 归属修正**：`agencyId` 取创建人 `user.agencyId ?? null`（当前取 `route.agencyId`），并落 `sourceRouteId`。
3. **发布/下线/删除权限放开（角色自发布）**：
   - `publish` / `unpublish` / `remove`：去掉无条件的 `assertPandaking`；改为 `assertCanManage(id,user)`（已是"本机构或本人"判断）+ pandaking 全域放行。即非 pandaking 仅能操作自己归属/创建的案例。
   - `translate`（AI 翻译）：保持 pandaking + 本机构 agency（既有）；provincial 如需补译本人案例，纳入 `assertCanManage` 范围。
4. **编辑权限放开**：`update` 中 `AGENCY_EDITABLE_FIELDS` 仅限翻译字段——需扩展为：当案例归属/创建人为本机构或本人时，允许全字段编辑（与 pandaking 同权）；他机构案例仍仅翻译字段。

### 前端 `Cases.vue`
1. 三个创建按钮保持全角色可见（现状已满足，无需改显隐）。
2. 文案替换：按钮、面板按钮、空状态、Hero 副标题按第 6 节。
3. 卡片操作区：按角色显示"发布/下线/删除"——`isPandaking` 任意；`isAgency && c.agencyId===user.agencyId` 显示发布/下线/删除/编辑；`isProvincial && c.createdById===user.id` 显示发布/下线/删除/编辑。其余他人案例维持"校对/只读"。
4. 派生面板 `fetchRoutes()` 范围：确保省地接社能看到其可参与的路线（技术专家核对路由权限，避免省地接社派生源为空）。

## 9. 风险与边界

- **品牌安全**：角色自发布降低平台审核门槛；以 PandaKing 的"下线/删除/接管"权作兜底，必要时后续可加"首次发布需 pandaking 审核"开关（本期不做）。
- **派生归属**：修正 `publishFromRoute` 的 `agencyId` 取自创建人，避免省地接社派生的案例被错误挂到某 agency 名下。
- **省地接社派生源**：需确认 `fetchRoutes` 对省地接社返回其可参与的路线，否则"从行程定制导入"对省地接社为空选项（技术专家落地时核对）。
