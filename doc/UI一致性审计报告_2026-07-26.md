# PandaKing9 前端 UI 一致性审计报告

> 审计日期：2026-07-26 · 范围：frontend/src 全量页面与组件
> 审计维度：视觉风格 / 布局结构 / 动效交互 / 响应式适配 / 色彩体系

## 一句话结论

全站存在 **三套并行的设计语言**，同一"品牌主色"在站内有 **蓝 / 青绿 / 红** 三种呈现，根因是上一轮"全站统一换蓝"只改了 `style.css` 全局 token，而**看板 + 详情页用了独立 token 作用域**、**H5 分享页残留旧红 fallback**。结构性不统一，需要一次统一重构，而非打补丁。

---

## 一、三套设计语言地图

| 体系 | 主色（primary） | 状态色来源 | 按钮类 | 使用页面 |
|---|---|---|---|---|
| **A. 全局蓝（基准，正确）** | 蓝 `--brand #185FA5` | `style.css` `.badge.*` | `.btn / .btn-primary` | Login、Cases、KnowledgeBase、Settings 及 6 个子页、NotifyDialog、RouteArchive(s)、Home、H5Invite、ChangePwd、H5Intake、H5CostInquiry、RoutePdf、QuoteTable |
| **B. 看板/详情 青绿 9 色（漂移）** | **青绿 `--teal-600 #0f6e56`** | 本文件内 `--teal/--blue/--purple/--amber/--green/--red/--gray-*` | `.k-btn / .d-btn` | **RouteKanban、RouteDetail**（最核心的两个控制台页） |
| **C. H5 分享页（残留红）** | 名义蓝，但多处 fallback 红 | `var(--brand-* , #旧红)` | 内联 | H5Route、H5ProvincialRoute（客户/协作方视角） |

> 用户路径最直观的断裂：登录页（蓝色"登录"按钮）→ 进入控制台看板，"新建路线 / 保存并报价" 却是**青绿**；客户打开 H5 链接，部分文字因 `--brand-700` 未定义而渲染成**红色**。

## 二、按维度发现（带严重级 P0–P3）

### 1. 视觉风格
- **[P0] 品牌主色三态**：蓝（体系 A）/ 青绿（体系 B 的 `.k-btn.primary`、`.d-btn.primary`）/ 红（体系 C 的 `--brand-700`）。同一 action 在三处颜色不同。
- **[P1] 状态色定义 3 份、色值互不一致**：以 `awaiting_quote` 为例
  - 全局 `style.css .badge.awaiting_quote` → `--info #2f6feb`
  - `RouteList.vue .badge.awaiting_quote` → 硬编码 `#e8f0fe / #2f80ed`（与全局近似但非同一来源）
  - `RouteKanban/RouteDetail .st-awaiting_quote` → `--blue-50/200/800`（更浅的蓝）
  - 同一语义状态，三套配方。
- **[P2] 徽章形态不统一**：全局 `.badge` 圆角 `999px`（药丸）；`RouteList .badge` 圆角 `6px`（小圆角非药丸）；看板/详情用 `.pill` 类（药丸，但类名不同）。`.badge` 与 `.pill` 是两个类表达同一概念。
- **[P2] 弹窗 3 种实现**：全局 `.modal-backdrop/.modal`（style.css，max-width 460，遮罩 `rgba(18,26,41,.5)`）；看板复用全局；`NotifyDialog` 自建 `.nd-mask/.nd-modal`（max-width 560，遮罩 `rgba(0,0,0,.45)`，关闭按钮样式不同）。
- **[P3]** 看板头像调色板硬编码 hex（装饰性，可接受但不 token 化）。

### 2. 布局结构
- **[P1] 断点混乱**：480 / 560(Cases) / 640(全局、Home) / 860(App 导航、Settings) / 900(看板) / 960(详情)。无单一断点真源。导致 640–860 的"平板带"里，部分页仍是双列、部分已折叠，体验不一致。
- **[P1] `RouteList.vue` 无响应式**：7 列 `.list-table` 未包 `.tbl-wrap`，移动端横向溢出/错位；而看板在同宽度已转卡片式 → 表格行为不一致。
- **[P2] 三套表格实现**：全局 `.tbl`(带 `.tbl-wrap` 横滑) / 看板自定义 grid `.table/.thead/.trow` / `RouteList .list-table`。
- **[P2] 卡片圆角不统一**：全局 `.card`=`--r-lg 16px`；看板/详情卡片 12–14px；Cases/KB/Settings 卡片 12px；Home 16px → 看板/详情的卡显得更"紧"。
- **[P3] 页头模式不一致**：全局 `.page-header/.page-title`（Cases/KB 用）；看板用自有 `.topbar <h1>客户看板</h1>`（非 `.page-title`）；详情用 `.head` 带返回键。控制台内"页头"三种写法。

### 3. 动效与交互
- **[P2] 按钮 hover 语义不同**：全局 `.btn:hover` 变 bg+border 为品牌色；看板 `.k-btn.primary:hover` 用 `filter:brightness(1.06)`（无色相提示）；`NotifyDialog .nd-btn:hover{opacity:.92}`；详情 `.d-btn` 仅 filter。悬停反馈跨页不一致。
- **[P2] 过渡缺失**：看板/详情 primary 按钮无 `transition`（仅 filter）；全局 `.btn` 有 `transition: background .15s…`。微交互节奏不一。
- **[P3] 加载态**：多为纯文本"加载中…"，无骨架屏/Spinner，且看板用卡片包裹、详情用裸文本，呈现不一致。
- **[P3] 键盘可达性**：全局 `.btn:focus-visible` 有 outline；看板 `.k-btn` / 详情 `.d-btn` / Settings `.side-item` **无 focus-visible** → 控制台键盘导航缺焦点环。
- **[P3] 删除确认 UX 不一**：Cases/KnowledgeBase 用浏览器原生 `confirm()`；看板/详情用自定义模态。

### 4. 响应式适配
- **[P1]** 断点混乱 + `RouteList` 移动端溢出（见布局）。
- **[P2]** 详情双列 `.cols` 在 960 折叠、看板统计在 900/640、Settings 侧栏在 860、全局规则在 640 → 800px 平板宽度下各页折叠时机错位。
- **[P3] 触控目标**：主按钮高度约 34–36px（`.k-btn`/`.d-btn`/`.btn` padding 9px），小于 44px 建议值；`sm` 变体约 28px（次要按钮，尚可）。

### 5. 色彩体系
- **[P0] `--brand-700` 未定义却被引用**：`H5Route.vue:1017 .day-chip-spot { color: var(--brand-700, #a60d26) }` → 落入红色 fallback，**实际渲染为红色**（全局 `style.css` 只定义 `--brand/--brand-600/--brand-50/--brand-100`，无 `--brand-700`）。蓝站中出现红字。
- **[P0] 残留旧红 fallback 地雷**：H5 两页 + `NotifyDialog` 大量 `var(--brand, #c8102e)`、`var(--brand-50, #fdeef0)`、`var(--brand-600, #a60d26)`、`var(--brand-100, #fbd5dc)`。`--brand` 现已定义故当下为蓝，但一旦 token 加载异常即回退红色；且说明换蓝迁移只做了一半。统计：H5Route 11 处、H5ProvincialRoute 5 处、NotifyDialog 3 处。
- **[P1] 9 色体系重复全局语义色**：`--teal-600 ≈ --ok`、`--blue-600:#185fa5 == --brand`（却另定义）、`--amber-* ≈ --warn`、`--red-* ≈ --danger`、`--green-* ≈ --ok`。"成功/警告/危险/信息"有两个真相源 → 必然漂移。
- **[P2] `--brand-soft` 未定义却被引用**：`RouteList.vue:90`、`SettingsRoutes.vue:91` 的 `.row:hover{background:var(--brand-soft)}` → 解析为透明，**悬停高亮失效（死样式）**。
- **[P3]** `NotifyDialog` 作为公共组件仍写 `var(--brand, #c8102e)` 旧红 fallback，应改为 `var(--brand)` 或新蓝 fallback。

## 三、正向发现（保留并复用）

- `style.css` 全局 token 体系扎实：流体间距 `clamp()`、统一字号阶梯、`.btn` 含 focus-visible，是合格的"基准系统"。
- Login / Cases / KnowledgeBase / Settings 家族**已正确**使用全局蓝 `.btn` 体系 —— 它们就是统一重构的参照样板。
- `Home.vue` 杂志风改版与蓝品牌自洽、完整。
- 状态按语义配色（每状态一色）的思路很好，只需收敛到单一来源。
- `RouteDetail` 的协作时间线 / 价格回调链路图信息密度高、目的明确。

## 五、推荐的统一重构方案（待你确认范围后执行）

1. **[P0] 收敛品牌主色**：看板/详情的 `.k-btn.primary`/`.d-btn.primary` 由 `--teal-600` 改为 `--brand`；9 色体系内的 `--blue-600` 等直接复用全局 `--brand/--brand-600`。
2. **[P0] 修 H5 红 bug**：定义 `--brand-700`（或把 `.day-chip-spot` 改 `--brand-600`）；全量替换 H5 + NotifyDialog 的旧红 fallback 为无 fallback 或新蓝 fallback。
3. **[P1] 收敛状态色到全局**：把看板/详情的 `.st-*` 与 RouteList 的 `.badge.*` 硬性值删除，统一引用 `style.css .badge.*`；必要时在全局 `.badge` 增补缺失状态类（如 `st-role`、`st-neutral`）。
4. **[P1] 统一断点**：在 `:root` 增加 `--bp-tablet:860px`、`--bp-mobile:640px`，全站替换散落的 `480/560/900/960` 媒体查询。
5. **[P2] 统一圆角/按钮/hover/焦点**：全站改用 `--r-*` token；看板/详情按钮改挂全局 `.btn` 体系（或至少补 `transition` + `:focus-visible` + hover 变品牌色）；`RouteList` 包 `.tbl-wrap` 并加移动端适配。
6. **[P2] 统一弹窗与表格**：`NotifyDialog` 对齐全局 `.modal` 规格；`RouteList` 复用全局 `.tbl` 或在窄屏转卡片。
7. **[P3] 清理**：删除 `--brand-soft` 死引用（改 `--brand-50`）；Cases/KB 删除原生 `confirm()` 改用统一模态（可选）。

> 改造原则（遵循你的长期要求）：先全局想清再统一改；改完 `vue-tsc` + `vite build` 校验；仅 `git add` 相关文件；push 后你控制台手动「重新部署」生效。
